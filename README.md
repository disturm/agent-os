# Wellness-агент

Локальный агент из одного файла: коуч по питанию, тренировкам, восстановлению и привычкам с обязательной проверкой безопасности.

Это **не медицинский продукт**. Диагнозы, лекарства, анализы и лечение — вне зоны ответственности: на такие запросы агент останавливается и отправляет к специалисту.

## Установка

```bash
npm install
```

Нужен Node.js 20+ (проверено на 24).

## Ключ DeepSeek

Скопируйте `.env.example` в `.env` и подставьте свой ключ с https://platform.deepseek.com/api_keys:

```
DEEPSEEK_API_KEY=sk-...
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
```

`DEEPSEEK_BASE_URL` и `DEEPSEEK_MODEL` необязательны: по умолчанию `https://api.deepseek.com` и `deepseek-v4-pro`. `deepseek-v4-flash` дешевле и быстрее, для этой задачи хватает.

## Запуск

```bash
npx tsx index.ts "составь план питания на завтра"
```

или через алиас (двойной дефис обязателен, иначе npm съест аргумент):

```bash
npm run agent -- "составь план питания на завтра"
```

Одобренный план пишется в `output.md`, в консоль идёт лог каждого раунда: номер, verdict, score, issues.

Проверить предохранитель:

```bash
npx tsx index.ts "подбери мне лекарство от давления"
```

Ожидаемо: `verdict=needs_human_professional`, низкий score, остановка, `output.md` не перезаписывается.

## Как это устроено

1. Задача берётся из аргумента CLI.
2. `profile.md` и `log.md` целиком подставляются в контекст.
3. **Health Coach** генерирует план.
4. **Safety Reviewer** проверяет его по трём критериям (безопасность, реалистичность, соответствие профилю) и отвечает строго JSON — валидация через Zod, на невалидный ответ один ретрай.
5. `revise` → issues уходят обратно коучу, максимум 3 раунда. `needs_human_professional` → остановка. `approve` → запись в `output.md`.

Оркестрация — в коде, а не в промпте. Инструментов и function calling у агентов нет: они работают только на контексте из файлов.

## Файлы

| Файл | Что это |
|---|---|
| `index.ts` | Весь оркестратор: клиент DeepSeek, оба системных промпта, схема Zod, цикл ревью |
| `profile.md` | Профиль: цели, ограничения, предпочтения. Правьте под себя |
| `log.md` | Дневник последних дней: еда, сон, тренировки |
| `output.md` | Последний одобренный план (перезаписывается) |

Никакой базы данных — только markdown.

## Настройка под себя

Замените содержимое `profile.md` и `log.md` — формат свободный, агенты читают их как есть. Чем конкретнее ограничения (травмы, аллергии, непереносимости), тем строже ревьюер отсекает неподходящие рекомендации.

Поведение агентов меняется в двух константах в `index.ts`: `COACH_PROMPT` (роль, формат плана, запреты) и `REVIEWER_PROMPT` (критерии, вердикты, шкала score).

## Коды возврата

| Код | Когда |
|---|---|
| 0 | План одобрен и сохранён, либо запрос корректно отклонён как медицинский |
| 1 | Нет аргумента или ключа, план не одобрен за 3 раунда, ревьюер дважды вернул невалидный JSON |
