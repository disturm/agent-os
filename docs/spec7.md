## Контекст
Next.js-приложение: агент Health Coach + Safety Reviewer, harness (loop, traces, evals, replay), собственный MCP-сервер src/mcp/markdownHealthServer.ts (stdio) с tools read_profile / read_recent_logs / append_daily_log / save_health_plan / list_recipes. Агент получает данные через этот MCP; shopping и workouts — локальные tools.



## Задача
Подключи внешние готовые MCP-серверы и покажи, что интеграция = конфиг, а не код.

1) Конфиг — src/mcp/servers.config.ts:
   Массив описаний серверов: { name, command, args, env?, enabled }. В нём:
   - markdown-health (наш сервер) — enabled: true
   - filesystem (@modelcontextprotocol/server-filesystem, доступ только к папкам data/ и plans/) — enabled: true
   - weather (готовый MCP-сервер прогноза погоды на базе Open-Meteo, БЕЗ API-ключа) — enabled: true.
     Найди актуальный поддерживаемый пакет в npm и проверь, что он запускается через npx по stdio
     и отдаёт tool прогноза по координатам/городу. Зафиксируй выбранный пакет в конфиге и README.
   - notion (официальный Notion MCP, @notionhq/notion-mcp-server) — enabled: false,
     включается автоматически при наличии NOTION_TOKEN в .env (internal integration token, без OAuth)

2) Подключение: harness читает конфиг и поднимает все enabled-серверы, отдавая их tools агенту единым списком.

3) Демо-сценарии:
   - weather: задача «спланируй тренировку на завтра с учётом погоды» — агент вызывает
     weather-tool, при плохой погоде переносит активность в зал. Мы не писали ни строчки интеграции.
   - filesystem: задача «сохрани мой план ещё и в отдельный файл plans/<дата>.md».
   - notion (при токене): задача «сохрани план страницей в мой Notion» — агент создаёт
     страницу через notion-tools.

4) Guardrails (двухуровневые, зафиксируй в README принцип «промпт — просьба, конфиг — стена»):
   - filesystem: allowed directories = только data/ и plans/ на уровне запуска сервера
     + правило в новой версии промпта коуча (healthCoach.vN.md)
   - notion: доступ ограничен правами самой integration — в Notion ей выдаётся только
     одна страница/база «Wellness»; в промпте — писать только туда
   - weather: read-only по природе, ограничений не требует (проговори это в README как пример
     того, что не все серверы одинаково опасны)
   - в промпт коуча добавь: при планировании тренировок на открытом воздухе учитывать прогноз



## Требования
- Добавление нового сервера = новая запись в servers.config.ts, ноль правок harness.
- Сервер с enabled: false и без нужного env-токена пропускается молча, без ошибок.
- В UI-списке «Что сделал агент» помечай источник tool-а: [markdown-health], [filesystem], [weather], [notion], [local].
- README: таблица подключённых серверов (пакет, что даёт, авторизация); список ещё 2–3 полезных MCP (Google Calendar, Database, Web Search) — только упоминание, без подключения, с пометкой, что Calendar требует OAuth и потому вынесен за скобки.



## Запрещено
- Не подключать серверы, требующие OAuth-флоу — максимум token из .env для notion (и только за флагом enabled).
- Не писать свои обёртки над внешними tools — агент получает их как есть.
- Не давать filesystem-серверу доступ выше корня проекта.
- Не хардкодить координаты/город для погоды в коде — агент берёт локацию из profile.md
  (добавь в профиль поле с городом, если его нет).
  - Не пиши тесты и tdd



## Definition of Done
- Демо «тренировка на завтра с учётом погоды» работает: в трейсе виден weather tool call,
  план ссылается на прогноз.
- Демо с сохранением файла через filesystem MCP работает.
- При наличии NOTION_TOKEN демо «сохрани в Notion» создаёт страницу; без токена сервер
  просто не поднимается и ничего не ломает.
- Отключение любого сервера в конфиге убирает его tools у агента без ошибок.
- В трейсах видны tools с префиксом источника.
